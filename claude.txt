HARD GOTCHAS (each cost real time this session, do not rediscover):
1. distro sunxi-tools/sunxi-fel CRASHES on A523 (aw_read_usb_response AWUS assertion). must use xfel built from github.com/xboot/xfel git HEAD.
2. `adb reboot fel` only blips FEL for <1s then continues booting - looks live but isn't. must use physical button combo (pwr off -> hold VolDown -> tap Pwr 2s release -> tap Pwr x3 more still holding VolDown -> screen must stay black -> plug USB). properly-entered FEL holds indefinitely.
3. fastboot on this SoC is a minimal 20-cmd stub: `fastboot flashing unlock` -> "unknown cmd" (must use old `fastboot oem unlock`); `fastboot getvar all` -> "secure mode limited" (expected, harmless).
4. flashing 8MB via FEL takes 8-15min (256x 32KB chunks, 1-bit@12MHz bus, PIO not DMA, 40KB SRAM only bc TrustZone blocks non-secure DRAM writes, ~3s BROM USB timeout forces chunking). NOT a hang, do not interrupt.
5. flashing disabled vbmeta(--flags 0x02) HALTS BOOT on this bootloader ("device is corrupt") unlike normal AVB warn-and-continue. never touch vbmeta; unlocked-orange state alone is enough.
6. pm uninstall --user0 writes to /data/system/packages.xml ASYNC. reboot within ~seconds of uninstalling silently reverts ALL removals (looked like "ROM restored packages" but was just unflushed state - confirmed by testing: same batch, waited 60s+verified mtime via `stat -c %Y packages.xml` vs `date +%s` before reboot second time, removals stuck). ALWAYS wait+verify flush before reboot.
7. removing GMS+GSF+com.google.mainline.*(adservices/telemetry, these are mainline MODULE METADATA not bloat)+sdksandbox+ondevicepersonalization+federatedcompute+cellbroadcastservice+captiveportallogin in one batch -> bootloop, required factory reset. root survived reset (init_boot untouched by data wipe); 41 non-GMS removals did NOT survive the reset and had to be redone. lesson encoded in script's BLOCKLIST array (refuses these pkgs even if user requests) + staged group1/group2 debloat commands + mandatory reboot-test between batches.
8. own mistake, corrected: netwatch.py polled `adb shell su -c ...` every 2s in a loop = su-grant-prompt spam on device. killed it; if reviving similar monitoring use ONE persistent root shell, not repeated su invocations.
9. own mistake, corrected in-convo: initially framed `fastboot oem unlock` as bundled under "just a reboot, reversible" - it is NOT, it's the irreversible full-wipe step, must be called out separately from mode-switching reboots.
